# G3 #3 — New SI Evidence Coverage (riskDetections + vulnerabilities)

This change is **additive only**. No existing signal transform, evaluator, control
mapping, or test expectation was altered or repointed.

## What was added

### New signal transforms (`src/eo/generation/SignalRegistry.ts`)

These endpoints were already fetched by `ComplianceSignalFetcher` but had **no
transform** (raw data only). They now have template/context transforms mirroring
the existing registry style:

| signalId         | endpoint                              | fields surfaced                                   |
|------------------|---------------------------------------|---------------------------------------------------|
| `riskDetections` | `/identityProtection/riskDetections`  | `riskType`, `riskLevel`, `riskState`, `detectedDateTime`, `userPrincipalName` (+ counts, high-risk count) |
| `vulnerabilities`| `/security/microsoft/vulnerabilities` | `id`, `severity`, `cvss`, `remediation` (+ counts, critical/high count) |

Both transforms tolerate `{ value: [...] }` and bare-array raw data, and fall
back across Graph field name variants (`riskEventType`/`activityDateTime`,
`cvssV3`/`cvssV2`/`cvss`, `remediation`/`description`).

### New evaluators (`src/eo/mapping/evaluators/si-evaluators.ts`)

Both follow the existing `EvaluatorFn` contract (`(signals) => { status, evidence }`)
and are auto-registered via `siEvaluators` → `evaluatorRegistry`.

- **`riskDetectionPostureEvaluator`** — SI flaw identification / monitoring.
  Consumes `riskDetections`. `not_met` when no signal is available; `met` when
  the signal is present with no detections, or all high/critical detections are
  remediated/dismissed/confirmedSafe; `not_met` when unremediated high/critical
  detections remain.
- **`vulnerabilityPostureEvaluator`** — SI flaw remediation (SI.L2-3.14.1).
  Consumes `vulnerabilities` (falls back to `vulnerabilitiesExpanded`). `not_met`
  when no signal is available; `met` when no open critical/high vulnerabilities;
  `not_met` when unremediated critical/high vulnerabilities remain.

### Control wiring (`shared/src/data/control-signal-registry.json`)

Additive — existing `evaluator` fields were **not** changed/repointed. The new
endpoints were added as optional (non-required) signals so the new evidence is
collected/associated with the relevant controls without affecting the existing
evaluators:

- `SI.L2-3.14.1` — added optional `/security/microsoft/vulnerabilities` signal.
- `SI.L2-3.14.6` — added optional `/identityProtection/riskDetections` signal.

(The shared `dist/data/control-signal-registry.json` is regenerated by
`npm run build` in `shared/` via `scripts/copy-data.cjs`.)

### Tests (`tests/assessment/evaluators/si-risk-vuln-coverage.test.ts`)

New fixture-based suite with factories for the two signals. Asserts:
- transforms extract the expected fields (including field-name fallbacks),
- empty signal → `not_met` for both evaluators,
- a passing (`met`) case for both evaluators,
- unremediated high/critical → `not_met`,
- evaluators are registered and never throw on empty/garbage input.

The existing `tests/assessment/evaluators/regression.test.ts` is unchanged.

## Manual verification step (cannot run in CI)

These tests are **fixture-based** and require no tenant. End-to-end collection
against the live **MS / GCC High** tenant requires real Microsoft Graph /
PowerShell credentials and cannot run in CI. To verify against a real tenant:

1. Authenticate the PowerShell `mgraph` session used by
   `SessionManager` / `ComplianceSignalFetcher` with GCC High Graph
   (`graph.microsoft.us`) credentials holding the required read scopes
   (`IdentityRiskEvent.Read.All`, `ThreatIndicators.Read.All` /
   Defender vulnerability read).
2. Run the full signal fetch (`fetchExpandedSignals`) and confirm the
   `riskDetections` and `vulnerabilities` signals return `status: 'success'`
   with populated `rawData`.
3. Confirm the SI control assessments for `SI.L2-3.14.1` and `SI.L2-3.14.6`
   include the new signals in their collected evidence.

Note: `/identityProtection/riskDetections` and Defender vulnerability endpoints
may surface differently or be unavailable depending on the tenant's licensing
(Entra ID P2 / Defender for Endpoint) in GCC High — verify availability as part
of the manual step.
