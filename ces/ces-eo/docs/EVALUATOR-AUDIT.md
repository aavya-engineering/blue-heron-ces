# Evaluator audit: what each EO evaluator actually tests

**Date:** 2026-10-27; updated 2026-10-28 (W5c1; W5c7 = synthetic-customer W5 cycle 7, AU.L2-3.3.7). **Origin:** EO-collection plan W0.4 (REVIEW P0 #4). **Status:** first pass, mechanical plus hand review of the 19 evaluators that do more than check presence. It is the hand-off for the contractors' per-requirement loophole audit ("gather each requirement's evidence; check the implementation for loopholes"); extend and correct it.

**Terms.**
- **EO** = EvidenceOps (this repo). **CA** = Conditional Access. **TVM** = Defender vulnerability management. **DLP** = data loss prevention.
- **W0.4, W0.3, W1.0, W2.9, C1a–C9, B15** = items and decisions in the EO-collection plan (`PLAN-eo-collection.md`, strategy repo, `docs/context/eo-collection/`): W0.x = wave-0 fixes; W1.0 = "unread is not absent" guard from the SSP-uplift plan; W2.9 = planned evaluator upgrades; C1a–C9 = the collectors (`src/eo/collect/`): C1a unified audit log, C2 directory audits, C3 sign-ins, C4 PIM activations, C5a/C5b risk detections and risky users, C6a/C6b Defender XDR alerts and incidents, C7a/C7b TVM assessment recency and software vulnerabilities (advanced hunting), C8 Secure Score history, C8b Secure Score control profiles, C9 Intune compliance; B15 = the founder's registry-change decision; B19 = the founder's decision that stale evidence never counts as positive.
- **Registry** = `ces-shared` `control-signal-registry.json` (which evaluator and signals score each control).

**Classes.**
- **tests a setting** = reads the configuration or records and decides from their content (a field, a state, a date window, a coverage ratio).
- **presence only** = returns `met` when the read returned any object. Since W1.0, an unread, errored or empty read gives `not_assessed`, not `not_met`; the claim in the narrative is still not tested.
- **W5c1** = synthetic-customer wave W5, cycle 1 (strategy repo `docs/context/synthetic-customer/LOG-W5c1-evaluators.md`): a rewritten evaluator tests its condition against the Tenant Manifest (TM) verification `expected_value` when the caller passes it (optional `ctx`, not yet wired by the mapper), else the requirement default in `conditions.ts` `REQUIREMENT_DEFAULTS`; an unread or empty read, or one that does not carry the setting, is not assessed with the read printed. **ODP** = organisation-defined parameter. **CA** = Conditional Access. **TAP** = Temporary Access Pass. **UPN** = user principal name.
- **record-based** = the requirement needs a record (a review, a rule, an incident file) that no read provides; returns `not_assessed` with the read printed (W0.4).

**Counts (89 evaluators):** tests a setting 69 (one with a presence fallback; four that test collected records since W2 part 1; and, since W2 part 2, seven that test collected security-monitoring records: 3.3.5, 3.6.1, 3.14.3, 3.14.6, 3.14.7, 3.11.2, 3.11.3; and, since synthetic-customer W5 cycle 1 (W5c1), 44 more: the AC and IA families and CM.L2-3.4.3/6/7/9, SC.L2-3.13.9/12, SI.L1-3.14.2/4/5, MA.L2-3.7.4/5, MP.L2-3.8.7/8; and, since W5 cycle 2 (EO-2), 4 more: CM.L2-3.4.2, SC.L1-3.13.1/5, SC.L2-3.13.6, from the settings catalog; and, since W5 cycle 7 (W5c7), AU.L2-3.3.7 from the settings catalog); presence only 16; record-based 3 (3.3.3, 3.3.4 and the manual gate); inherited, not tested 1 (IA.L2-3.5.11, W5c1 addendum). Every default bound prints 'requirement default, no organisation value'; a TM value prints 'organisation value: TM expected value (source)'. Since the W5c1 addendum the mapper passes the TM (expected values, break-glass and admin account ids) to every evaluator.
