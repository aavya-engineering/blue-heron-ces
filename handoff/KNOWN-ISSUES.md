# Known issues

Problems known at the release cut that a contractor will meet when building, running or proving CES. Each entry has an id, the symptom, the workaround, a severity and an owner. Read this before you report a failure: if it is listed, follow the workaround and note the id in your report. Open work that is not a symptom you will meet (features to finish, decisions to take) is in `PUNCH-LIST.md`, not here.

- **Id:** `KI-nn` (known issue, number nn). Ids are never reused; a fixed issue stays listed with its fix.
- **Severity:** **high** = blocks bootstrap or acceptance until worked around or fixed; **medium** = a workaround is needed for some runs; **low** = information, or a cosmetic issue. "(live)" = only on a real tenant.
- **Owner:** **BHD engineering** = a code fix in the CES repos (after handoff, whoever BHD assigns, often the contractor); the **BHD owner** decides or grants something; the **contractor** applies the workaround.
- File paths are relative to the workspace `<Root>\ces` (the ces-mono root) unless they start with `<PKG>` (the run package `ces-muster-run`; in the contractor monorepo it is `<Root>\pkg\ces-muster-run`).
- Refreshed 2026-11-01 by H1 (handoff agent 1; brief `AGENT-BRIEF-HANDOFF2.md`) to the PH-13 code. PH-13 is BHD's last fix wave before the handoff; PH-7 is an earlier wave that changed the network and secrets defaults.

## Legend
- **KI-nn**: a known-issue id in this file. **PH-n**: a BHD fix wave (PH-7 network and secrets, PH-13 the last wave before handoff). **R-Fn**: proof round n. **H1**: the handoff agent that refreshed this file.
- **AO / EO / EC**: AdminOps (`ces-ao`, governed admin commands, including the leaver flow), EvidenceOps (`ces-eo`, evidence, assessment, SSP and SPRS), Evidence Collector (`ces-ec`, evidence uploads). **Stamper** (`ces-stamper`): applies the configuration plan to the tenant. **Muster** (`ces-muster`, API `muster-api`): data collection and plan writing.
- **S1 / S2 / S3 / mp**: the simulator's synthetic customer scenarios `s1-mach`, `s2-eng`, `s3-def`, `muster-partial` (`tenant-stacksim\scenarios\`).
- **V-nn**: a verify check in `<PKG>\scripts\verify.mjs` or a `verify-*.mjs` file it loads; ACCEPTANCE.md lists them all. **E-step (E2, E7B, EL)**: a step of `<PKG>\scripts\mx-e2e.ps1` (EL = the proposed leaver step).
- **FIX-KIT**: the BHD agent pass that fixed this kit after the clean-room test (BHD's test of the kit from a fresh clone, run as a contractor would, 2026-11-01). **PL-nnn**: a row in `PUNCH-LIST.md`.
- **FIX-MONO**: the BHD agent pass of 2026-11-02 that fixed the clean-clone findings CR-13 to CR-25 (and PL-120); its log, LOG-FIX-MONO.md, is a BHD planning log, not shipped. **delivered_copy**: the flag on an AO outbox message whose clear confirm link is still held in the AO server's memory (PL-122).
- **WORM**: write once, read many. **JWT**: JSON Web Token. **DPAPI**: Windows Data Protection API, which protects the module-secret store. **SPRS**: the DoD Supplier Performance Risk System score. **SSP**: system security plan. **CRLF / LF**: Windows / Unix line endings.
