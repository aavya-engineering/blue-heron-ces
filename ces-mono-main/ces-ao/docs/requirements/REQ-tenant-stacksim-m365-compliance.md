- **Evidence:** `ces-ao/docs/AO-95-OP-MATRIX.md` (generated by `test/integration/ao95.matrix.stacksim.test.ts`, stacksim `m365_azure`, dist of branch `gp-demo-1-stacksim-p02` @ 9170eb8)

## What

The EXO / Purview / SharePoint / PnP / unified-audit-log family — the largest cluster, as the tester's gap review predicted.

AO behaved correctly on every op below: the governed pipeline ran, the command reached the sim through the shims,
exactly one contract-conforming evidence row was written per request, and every applicable deny was proven. What is
missing is on the sim side: the response does not contain what the command needs, or the write does not land where the
paired read looks. Since W4-AO1, AO records the REAL before/after state, so a write that "succeeds" without changing
what its read observes is now visible (pre == post) instead of hidden behind a placeholder.

## Root causes seen

1. **`Search-UnifiedAuditLog` returns nothing for every record type AO asks for** (D-01, D-02, D-04, D-10, E-02..E-10, F-04, G-04,
   G-07, H-05). Seed audit records per `-RecordType` / `-Operations` AO sends (SharePointFileOperation, SharePointSharingOperation,
   ComplianceDLPExchange/SharePoint, AzureActiveDirectory, SecurityComplianceCenterEOPCmdlet with New-/Set-ComplianceCase, ...) inside
   the `-StartDate/-EndDate` windows AO uses (1 to 365 days), including deliberate "gap" records.
2. **`Get-DlpCompliancePolicy` returns nothing** although `dlpCompliancePolicy` is seeded (D-02 shows only the IPPS connection banner).
3. **`Get-Label` does not find the seeded label** `CUI//SP-CTI` (seeded in `sensitivityLabels`), so D-11 fails "label not found" (the
   coverage harness seeds a label that a profile serve lacks).
4. **Compliance-case writes not visible to the paired read** (D-03: `New-ComplianceCase` + `New-CaseHoldPolicy`).
5. **PnP / SPO:** `Get-PnPListItem` (G-06) and `Get-SPOTenant` (D-04) return nothing; no PnP.PowerShell shim module.
