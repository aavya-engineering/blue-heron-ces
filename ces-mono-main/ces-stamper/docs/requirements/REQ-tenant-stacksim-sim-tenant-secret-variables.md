# REQ: sim tenant record must carry approver_upn, initial_password, tou_file_base64 (tenant-stacksim)

**Filed by:** ces-stamper, Wave 4 step W4-ST2 (2026-09-27)
**Status:** OPEN
**Blocks:** W4-ST2 exit criterion "0 unresolved-variable warnings in a stacksim dry run" (HONEST-OPEN)

## What

Add three keys to `buildSimTenantConfig().resources` in `tenant-stacksim/src/config/SimTenantConfig.ts`
(every stance; they are M365 identity-side values):

| resources key | Stamper variable | Needed by (registry entry) | Suggested sim value |
|---|---|---|---|
| `approver_upn` | `approverUPN` | `AC.L2-3.1.4.pim-approval` | a seeded sim user, e.g. `sim.user3@simtenant.onmicrosoft.us` |
| `initial_password` | `initialPassword` | `AC.L2-3.1.6.admin-account` | a fixed, obviously fake sim literal (never a real secret) |
| `tou_file_base64` | `touFileBase64` | `AC.L2-3.1.9.terms-of-use` | base64 of a tiny fixed text/PDF stub matching `tou_file_name` |

Rebuild `dist/` after the change (Stamper's tests import `dist/src/config/SimTenantConfig.js`).

## Why

W4-ST2 translates Muster's committed goldens (mission plan + tenant manifest + W4-MU1 infrastructure manifest)
with the sim tenant record generated by `buildSimTenantConfig` and no hand-supplied variables. Every required
variable resolves except these three: no Muster artifact, no stacksim record and no Stamper default produces
them. A default password or terms-of-use file in Stamper would be wrong on its face; in a sim they are test
data, and the sim record is where test data for the sim tenant belongs.

## Acceptance

`ces-stamper/tests/unit/MusterInfraManifestTranslate.test.ts`:
- `it.failing('W4-ST2 criterion: 0 unresolved-variable warnings ...')` starts failing (i.e. the strict check passes)
  — Stamper then flips it to a normal `it` and drops the residual-set assertion.
- Stamper already maps all three names (`src/shared/variable-map.ts`: `approverUPN`, `initialPassword`, `touFileBase64`).

## Not in scope

Runtime variables `breakGlassUserId` and `baselineTemplateId` are also unproduced in that plan (no capturing
command is in scope); they are reported separately as `UNRESOLVED_RUNTIME_VARIABLE` and are not part of this REQ.
